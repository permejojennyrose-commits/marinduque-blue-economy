### Experiment B: Role Assignment

**Exact Prompt:**  
> Act as a frontend accessibility reviewer. Examine the generated Baybay Marinduque Marine Catch & Eco-Fisheries Portal interface. Identify problems involving HTML semantics, keyboard access, labels, and visual clarity. Recommend targeted improvements without changing the project's scope.

**Actual Copilot Output:**  
Copilot acted as a technical reviewer and provided an Accessibility Review table categorizing findings by Priority, Area, Finding, and Targeted Improvement:
1. **Keyboard Focus (High):** Identified that global focus rings are overridden (`outline: 0` / `outline: none`) on search and input fields. Recommended restoring `:focus-visible` outlines.
2. **Screen-Reader Updates (High):** Noted that the entire card grid has live region behavior (`aria-live`), causing excessive screen-reader announcements on every search keystroke.
3. **Text Contrast (High):** Flagged low contrast ratios on seller text (3.63:1) and card background footnotes (2.84:1) below WCAG AA 4.5:1 standards.
4. **HTML Semantics & Labels (Medium):** Suggested using `<fieldset>` and `<legend>` for filter groups, linking `<output>` labels via `aria-labelledby`, and adding item-specific accessible names to buttons (e.g., *"Estimate order for Yellowfin Tuna"* instead of generic repeated labels).

**What Worked:**  
* Copilot shifted from standard code generation to a structured analytical auditor role, identifying specific WCAG accessibility bugs with exact code references.
* Recommendations were highly targeted and practical without introducing unnecessary framework dependencies.

**What Needs Improvement:**  
* Copilot identified the accessibility bugs in a table format but required a follow-up prompt to apply the actual CSS and HTML code fixes.

**Observation:**  
Assigning a specialized persona (Role Assignment) prompts the AI to evaluate code through a domain-specific lens, surfacing usability and WCAG compliance insights that standard functional prompts miss.

## Task 5 - Structured Reasoning and Refinement

**Objective:**  
Use AI-assisted analysis to identify and improve a specific implementation weakness by requesting a diagnosis, targeted correction, and verification procedure.

**Exact Prompt:**  
> Review my Baybay Marinduque Marine Catch & Eco-Fisheries Portal interface code. Check whether the interactive price calculator works correctly, whether the HTML uses appropriate semantic elements, and whether the interface is usable on mobile screens. Identify the two most important implementation issues based on the provided code. Recommend the smallest appropriate corrections and explain how I can test them.

**Actual Copilot Output:**  
Copilot confirmed that the price calculator arithmetic and semantic HTML baseline were correct, but diagnosed two key implementation issues:
1. **Missing Data Property Rendering:** In `script.js`, the catch card renderer reads `item.availability`, but the catch records do not define this property, causing cards to potentially display "undefined".
2. **Mobile Readability & Navigation Suppression:** At smaller viewport widths (<600px), secondary font sizes shrink down to 7–10px, and the "Eco-fishing guide" link becomes hidden from the main navigation bar.

**Selected Correction:**  
Selected Issue #1 (Fixing missing `availability` values in `script.js` array objects) and updated the `for` attribute association on the price calculator output label.

**Verification Procedure & Result:**  
* **Test Step:** Added explicit `availability: "Available daily"` attributes to all catch records in `script.js` and loaded the browser preview. Tested the calculator by selecting *Yellowfin Tuna* at 0.5 kg to confirm the total dynamically calculates to ₱210.00.
* **Result:** Successfully verified in the browser—no "undefined" badges appear on any cards, and the price calculator updates instantly upon input change without errors.

**Observation:**  
AI-assisted code reviews effectively diagnose subtle edge cases (like rendering undefined object properties or accessibility label mismatches) that are easy to overlook during initial UI layout development.
